# Conversation-to-Note Skill

> 대화에서 지식을 추출하여 metanotes 볼트에 저장하는 스킬

## 노트 포맷

### 프론트매터 (YAML)

```yaml
---
created: YYYY-MM-DD HH:mm
title: "노트 제목"
tags:
  - type/{노트유형}
  - topic/{주제}
  - (추가 태그들)
source: "대화에서 언급된 URL이 있으면 기재, 없으면 비워둠"
---
```

### 태그 규칙

**type 태그** (노트의 성격, 하나만 선택):
- `type/insight` — 대화에서 도출된 인사이트, 오해 교정, 프레임워크
- `type/technical` — 기술적 개념 정리, 학습 노트
- `type/decision` — 의사결정 기준, 판단 프레임워크
- `type/clipping` — 외부 자료 요약/스크랩

**topic 태그** (주제 영역, 복수 가능):
- `topic/ai`, `topic/mcp`, `topic/hr`, `topic/dev`, `topic/pkm` 등
- 대화 내용에서 자동 추출

**추가 태그** (자유형, 대화에서 자동 추출):
- 구체적 키워드: `LLM`, `도구`, `스킬`, `에이전트`, `AX` 등
- 관련 프로젝트: `project/davinci-mcp`, `project/ax-tf` 등

### 본문 구조

```markdown
# {제목}

> 한 줄 요약 (이 노트의 핵심을 한 문장으로)

---

## 핵심 인사이트

- 번호 없이, 대화에서 도출된 핵심 내용을 3~7개로 정리
- 각 항목은 1~2문장으로 압축
- 단순 사실 나열이 아니라 "그래서 뭐가 중요한데?"에 답하는 형태

## ⚠️ 오해했던 것과 실제

이 섹션은 대화 중 기존 생각이 교정된 부분이 있을 때만 포함한다.

### 오해: {오해 내용 요약}
**실제**: {교정된 내용}
**왜 중요한가**: {이 교정이 실무에 어떤 영향을 주는지}

## 다이어그램

(계층·흐름·비교 구조가 있으면 Mermaid 다이어그램으로 시각화. 해당 없으면 이 섹션 전체 생략)

## 실무 적용

- 이 인사이트를 당장 어디에 쓸 수 있는지
- 구체적인 액션 아이템이나 판단 기준

## 연결 노트

- [[관련 노트 제목]] — 대화에서 언급된 관련 주제
```

## 작성 원칙

### DO
- 대화의 흐름을 따르지 말고, 결론 중심으로 재구성
- 사용자의 말투와 표현을 살려서 자연스럽게 (딱딱한 보고서 톤 X)
- "⚠️ 오해했던 것과 실제" 섹션은 대화에서 실제로 인식 전환이 있었을 때만
- 태그는 대화 내용에서 자동 추출하되, 기존 metanotes 태그 패턴과 일관성 유지
- 불필요한 섹션은 과감히 생략 (모든 섹션을 채울 필요 없음)
- 계층·흐름·비교 구조가 있으면 Mermaid 다이어그램으로 시각화

### DON'T
- 대화 전체를 그대로 옮기지 않는다 (대화록 X, 지식 노트 O)
- 뻔한 내용을 장황하게 늘리지 않는다
- 메타데이터를 과도하게 넣지 않는다 (Keep it simple)
- "Claude와의 대화에서..." 같은 출처 표기 불필요
- SVG, HTML, 인터랙티브 위젯은 절대 사용하지 않는다 (Obsidian 렌더링 불가)
- 억지로 다이어그램을 끼워 맞추지 않는다 (텍스트가 더 나을 때는 텍스트로)

## Mermaid 다이어그램 가이드

Obsidian은 Mermaid를 네이티브 렌더링한다.

**넣어야 할 때**: 계층 관계, 순서/흐름, 비교 구조, 포함/참조 관계
**생략할 때**: 텍스트 목록으로 충분한 경우, 억지로 끼워 맞추는 느낌

**호환성 주의**:
- 노드 안 줄바꿈은 `<br/>` 사용 (`\n` 금지)
- quadrantChart 축 레이블은 영문으로만 작성
- 노드 10개 이하 유지
